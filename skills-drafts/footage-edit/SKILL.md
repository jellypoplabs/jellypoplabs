# 剪真实素材

AI 视频 skill 管的是「生成画面」，这个管的是「剪已经拍好的东西」。长素材剪辑最常见的失败不是渲染出错，而是：

- 删多了：把讲解的半句话、动作的起势删掉，看着跳。
- 删少了：等待、调设备、重复的第 6 到第 10 次都留着，观众划走。
- 切片没有钩子：前 3 秒没说清这条讲什么。
- 加速段还留着人声，叽叽喳喳听不清。

所以核心规则是：**先出方案表给人审，再渲染。** 方案改起来几秒钟，片子渲染一遍要几分钟。

## 铁律

1. **AI 写方案，人拍板。** 剪辑方案（plan.json）写完先跑 `--review` 给用户看表，用户确认后才渲染。
2. **不看画面不定删。** 只读逐字稿会误删「没说话但在做示范」的段落。每个删除和加速，都要对着抽帧拼图确认过画面。
3. **交付前走 `ai-video-check` 的第 4、5 步。** 渲染完对每个成片跑 `render_check.sh`，看抽帧拼图。加速静音段会被报「静音」，那是故意的，交付时说明即可。

## 需要

- ffmpeg、Python 3、Pillow（`pip install pillow`）
- 转写：`pip install faster-whisper`，第一次运行会下载模型（需要能访问 huggingface）。没有也能剪，只是少了逐字稿和字幕。

## 流程

### 1. 体检素材

```bash
python3 scripts/scan.py 素材.mp4 --motion
```

输出在 `素材_scan/`：
- `summary.md`：时长、分辨率、有没有声音、静音段排行、画面静止段排行。
- `sheet_XX.jpg`：带时间的抽帧拼图（默认整片约 120 张，`--every 秒` 可调）。

`--motion` 检测画面静止，1 小时素材要多跑几分钟。课程录像建议开，口播可以不开。

### 2. 转写

```bash
python3 scripts/transcribe.py 素材.mp4 --model small
```

输出 `transcript.md`（`[mm:ss-mm:ss] 一句话`，给 AI 读）、`transcript.json`（出片时换算字幕用）、`transcript.srt`。专有名词（动作名、品牌）转写常错，进方案前顺手改 json。

### 3. 先问清楚，再写方案

动手写方案前问用户（已经说过的不再问）：

- 成片给谁看、发哪里：完整课程回放、付费课、抖音/小红书切片？
- 整片目标时长大约多少？切片要几条，每条多长？
- 有没有一定要留 / 一定要删的段落？
- 竖屏切片时人站在画面哪边（决定 `crop_x`）？

### 4. 写剪辑方案 plan.json

对照 `summary.md`、`transcript.md` 和拼图，复制 `templates/plan.example.json` 改写。每段写 `note` 说明为什么这么处理。

```bash
python3 scripts/render_plan.py plan.json --review
```

把审核表原样给用户看，等确认。表下面「需要注意」里的每一条要么改掉，要么说明为什么保留。

### 5. 出片

```bash
python3 scripts/render_plan.py plan.json --preview    # 480p 快速预览，先看节奏
python3 scripts/render_plan.py plan.json              # 正式版
python3 scripts/render_plan.py plan.json --only hl_02 # 只重出某一条
```

每个成片旁边生成换算好时间的 `.srt`，导进剪映改样式、烧字幕。加速静音段不出字幕。

### 6. 自检和交付

对每个成片跑 `ai-video-check` 的 `render_check.sh`，看拼图，重点看：
- 每个剪切点前后：话有没有被切半句，动作有没有从中间开始。
- 竖屏切片：人有没有被裁出画面，关键内容避开底部 25%。
- 切片单独看能不能懂（可以按 `ai-video-check` 第 6 步做盲测）。

交付时说明：删了多少、加速了哪几段、哪些没检查（比如声音要用户自己听）。

## 方案格式

```json
{
  "source": "素材.mp4",
  "transcript": "素材_scan/transcript.json",
  "out_dir": "out",
  "outputs": [
    {"name": "full_edit", "segments": [
      {"start": "00:05", "end": "03:40", "action": "keep",  "note": "开场讲解"},
      {"start": "03:40", "end": "04:10", "action": "cut",   "note": "调垫子"},
      {"start": "04:10", "end": "06:00", "action": "speed", "speed": 4, "audio": "mute", "note": "重复动作"}
    ]},
    {"name": "hl_01_xxx", "aspect": "9:16", "crop_x": 0.4, "segments": [ ... ]}
  ]
}
```

- `action`：`keep` 原速，`speed` 加速（`speed` 2–8，`audio` 填 `keep` 变速不变调或 `mute`），`cut` 删除。没写进 segments 的时间一律不要；`cut` 写出来只是让审核表看得到删了什么。
- `aspect`：不写就是原画幅；`9:16`、`1:1`、`4:5`、`3:4` 会居中裁切，`crop_x` / `crop_y`（0–1）调裁切中心。
- 时间写 `秒数`、`mm:ss` 或 `hh:mm:ss`，都可以带小数。
- 切片里的段落默认按时间顺序；要先放结论再倒叙，写 `"allow_reorder": true`。

## 场景规则

### 口播

- 删：开机等待、口误重说（保留最后一遍）、超过 0.6 秒的停顿、「嗯」「那个」。
- 剪切点落在句尾停顿里，不切在词中间。转写的时间会差 0.1–0.3 秒，拿不准时往外放 0.15 秒。
- 一个剪切点前后画面几乎一样会「跳一下」：连续跳切太多，提醒用户在剪映里加放大/缩小或 B-roll 盖住。
- 整片节奏参考：每 5–8 秒有一个新信息点。

### 访谈 / 播客切片

- 先从逐字稿里找「金句」：观点鲜明、有反差、有具体数字或故事的一段，能脱离上下文听懂。
- 每条切片 30–90 秒，开头 3 秒就是钩子：可以把结论那句话提前放（`allow_reorder`），再接完整的来龙去脉。
- 问题太长就只留最后一句；回答保持完整，不要把论证的中间删掉。
- 双人画面竖屏：谁说话裁谁，同一条切片里换人就拆成两个 output，或交给剪映做自动跟随。

### 课程录像（普拉提、瑜伽、健身、讲课）

整节课精剪：
- **原速**：讲解要点、第一次完整示范、纠正提示（「肩膀放松」「肋骨收住」）。
- **加速 3–6x 静音**：同一个动作的重复次数，留 2–3 次原速让人看清楚，其余加速只留节奏。配一行字「×10」在剪映里加。
- **删**：开机、调设备、换器械、喝水、找音乐、和课程无关的闲聊。
- 动作切换的过渡：保留起势和收势各 1–2 秒，不要从动作中间开始。
- 静音段 ≠ 可删：跟练时老师可能没说话但在示范。静音段对照拼图再决定。

单独切片（最好用的片段）：
- 一条切片只讲一个动作或一个要点：「这个动作最常见的错误」「×× 动作三个细节」。
- 结构：钩子（错误示范或结果）→ 要点讲解原速 → 正确示范（可 2x）→ 结束。
- 讲解原声一定保留原速；示范段加速后可以配音乐。
- 竖屏裁切时，躺姿、跪姿的人横向占满画面，9:16 会裁掉头或脚：先看拼图，裁不下就用 `4:5` 或 `1:1`，或者在剪映里做上下留白。

## 常见坑

| 现象 | 原因和做法 |
|---|---|
| 剪切点吞掉半个字 | 转写时间有误差。起点往前、终点往后各放 0.15 秒 |
| 加速段声音尖、听不清 | 超过 2x 的人声基本听不清。设 `audio: mute`，在剪映里配音乐 |
| 竖屏切片人被裁掉一半 | 默认居中裁。看拼图里人的位置，改 `crop_x`；躺姿用 4:5 或 1:1 |
| 竖屏切片糊 | 1080p 横拍裁成 9:16 只剩约 600px 宽，要放大近 2 倍。审核表会提醒；以后要出竖屏切片，用 4K 拍或另架一台竖拍 |
| 手机素材画面是横的 | 手机竖拍带旋转标记，脚本已按旋转后的宽高处理；还不对就先用剪映导出一遍 |
| 静音检测把轻声讲解当静音 | 环境噪音大或收音远。调 `--silence-db -40` 或 `-45` 再扫 |
| 整片几十段，渲染很慢 | 先 `--preview` 看节奏，满意了再出正式版；一次只跑一个渲染 |

## 越用越准

每剪一条真实素材踩到新坑，加进上面的表，或补进对应的场景规则。
